The Polymorphic Generator

A program that repaints itself on every run — new bytes, new fingerprint, identical behaviour. Hit “Run” below and watch the file mutate in real time.

01 Watch it mutate

Each run swaps one tiny value — the MUTATION_TOKEN — for a new random one and re-saves the file. That alone changes the whole file's fingerprint. Everything else stays put.

02 Why change the fingerprint?

A classic scanner recognises known-bad files by a hash. Change one byte and that hash is useless. Click “Run” above a few times, then compare the two defenders below.

🔎 Fingerprint-only scanner

Compares the file's hash against a blocklist. If the hash is new, it has never seen it.

verdict: unknown file → allowed ✗ missed

🧠 Behaviour-based defence

Ignores the look of the file and watches what it does when it runs.

verdict: same actions every run → flagged ✓ caught

03 What happens each run

🎒

Carry payload

An encrypted payload plus a random token live inside the generated source.

polymorphic._build_source()
🖊️

Rewrite self

It opens its own file, replaces the old token with a new one, saves.

_update_signature()
🔀

New hash

Different bytes → different SHA-256. The logic is untouched.

hashlib.sha256(file)
✅

Verify + run

Integrity-checks the payload, then executes it (in the isolated lab).

_recover_payload() · exec()

04 The frozen-.exe catch

A plain script edits itself directly. A packaged .exe is locked while running — so it writes the next generation beside itself and launches that, with a counter so it stops.

prog.exe → prog.gen1.exe → prog.gen2.exe → prog.gen3.exe → stop (max generations)
Defender's takeaway: if the file keeps changing but the behaviour doesn't, stop trusting the fingerprint and start watching the behaviour. That's the whole lesson polymorphism teaches.
