🔐 Evasion Tool — Walkthrough

Hidden-Bytes Project  |  For non-technical stakeholders  |  Safe educational edition

What this tool does in plain language:
The Evasion tool takes any ordinary file (for example, a small program that prints "Hello, World!"), locks it inside an encrypted container, pads it up to a requested size, and packages it as a single self-extracting file that waits for a delay, then unlocks and runs the original program. Nothing is executed during the encryption step — the output is just data.

1. The Three Modes at a Glance

1
--encrypt
Locks a file into an encrypted container or self-extracting runner. Adds padding and delay.
▶
2
--decrypt
Unlocks a container using the sidecar key file and writes the original file back to disk.
▶
3
--inspect
Shows what is inside a container without unlocking it (size, delay, name).

2. How Encryption Works (Step by Step)

1
Read the file
The tool reads the original file's bytes into memory.
▶
2
Generate a random key
A fresh 256-bit random AES key is created. No password is needed.
▶
3
Encrypt
The file is locked with AES-256-GCM. Only the key can unlock it.
▶
4
Add metadata
Name, size, delay, and a nonce are stored in a JSON header.
▶
5
Pad to size
Random filler is added so the final file reaches the requested size (e.g. +101 MB).
▶
6
Save + key file
The container is saved, and the key is written to a separate .key file.

⚠️ Platform Note — .exe Is Windows Only

.exe files only run on Windows. The subject requires a Windows VM for the .exe demonstration. On Linux/macOS, use an output name without .exe (e.g. evaded_program or evaded_program.pyz) — it will be a self-extracting Python script that runs with python3.

🪟
Windows VM
Output: evaded_program.exe — real native executable.
🔄
🐧
Linux / macOS
Output: evaded_program — run with python3 evaded_program.

3. What Gets Produced

evaded_program  •  evaded_program.key

evaded_program — the self-extracting runner. It contains the locked payload and waits before launching it.

evaded_program.key — the sidecar key file needed to unlock the container later. Keep it private.

(On Windows, the output name would end in .exe instead.)

5. The Delay — Enforced by the File Itself

When you run the produced file, it waits for the configured delay (for example 101 seconds), then unlocks and launches the original program. The delay is built into the file — the tool does not need to be running.

▶
Run the file
The artifact starts.
⏳
⏱
Waits
Stays idle for the delay (e.g. 101s).
🔓
📦
Unlocks
Decrypts the payload to a temp folder.
▶
🚀
Launches
Runs the original program.
$ ./evaded_program.exe
[INFO] Execution delayed by 101 seconds...
[INFO] Binary decrypted successfully.
[INFO] Target program executed.
Hello, World!

6. Example Commands

$ ./evasion --encrypt simple_program --output evaded_program --add-size 101 --delay 101
$ ./evasion --inspect evaded_program
$ ./evasion --decrypt evaded_program --output recovered --key evaded_program.key --no-delay
