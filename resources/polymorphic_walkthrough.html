The Polymorphic Generator

A compiled Go binary that re-encrypts its own payload on every run — new key, new padding, new ciphertext, completely different file hash, identical behaviour. Hit "Run" below and watch the binary mutate in real time.

01 Watch it mutate

Each run re-encrypts the payload with a fresh random AES-256 key, generates new random padding (1–64 KB), and rewrites the entire binary on disk. The stub stays the same; everything after it changes completely.

02 Why change the fingerprint?

A classic scanner recognises known-bad files by a hash. Change the encrypted region and that hash is useless. Click "Run" above a few times, then compare the two defenders below.

🔎 Fingerprint-only scanner

Compares the file's hash against a blocklist. If the hash is new, it has never seen it.

verdict: unknown file → allowed ✗ missed

🧠 Behaviour-based defence

Ignores the look of the file and watches what it does when it runs.

verdict: same actions every run → flagged ✓ caught

03 What happens each run

🎒

Carry payload

An AES-256-GCM encrypted payload is appended to the compiled stub, along with JSON metadata and a trailer.

generate.go → generateBinary()
🔄

Re-encrypt & rewrite

Generate a fresh random key and nonce, re-encrypt the payload, add new random padding, overwrite self on disk.

stub.src → rand.Read(newKey) · gcm.Seal()
🔀

New hash

Different key + different padding + different ciphertext = completely different SHA-256. The logic is untouched.

sha256sum polymorphic.exe
✅

Verify + run

AES-GCM tag authenticates the payload before execution. Python payloads run via python; binaries run directly.

stub.src → gcm.Open() · exec.Command()

04 Binary-level polymorphism

The output is always a compiled Windows .exe that can rewrite itself on every run. On Windows, a running .exe cannot be overwritten in place — but it can be renamed. The stub renames itself to .old, writes the new version at the original path, and continues.

On each execution:
1. Read self → parse trailer backward → decrypt payload
2. newKey = crypto/rand (32 bytes), newNonce = crypto/rand (12 bytes)
3. newCiphertext = AES-256-GCM.Seal(payload, newKey, newNonce)
4. newPadding = random 1–64 KB
5. os.Rename(self, self+".old") → write new binary at original path
6. [INFO] Polymorphic signature updated successfully.
7. Write payload to temp → execute → clean up
Defender's takeaway: if the file keeps changing but the behaviour doesn't, stop trusting the fingerprint and start watching the behaviour. That's the whole lesson polymorphism teaches.
